### Q1. SWE-agent (Princeton, 2024): which agent-computer-interface (ACI) choices moved SWE-bench, and by how much? mini-SWE-agent: why "100 lines + bash" and what did it score?

**Takeaway**
SWE-agent's paper is the clearest controlled evidence that the *interface*, not just the model, moves agent scores: on SWE-bench Lite with GPT-4 Turbo the full ACI scores 18.0%, and removing any one design choice (linter-guarded edits, summarized search, a 100-line file-viewer window, keeping only the last 5 observations) costs 1.7 to 7.7 points. mini-SWE-agent (2025) then showed that with stronger models a ~100-line bash-only ReAct loop reaches >74% on SWE-bench Verified, i.e. most of the 2024 scaffolding is no longer needed for frontier models.

**Cited Findings**
- SWE-agent paper: arXiv 2405.15793, v1 6 May 2024, v2 30 May 2024, v3 11 Nov 2024; abstract reports 12.5% pass@1 on SWE-bench (full) and 87.7% on HumanEvalFix. — [arXiv abstract](https://arxiv.org/abs/2405.15793)
- Main results (% resolved, avg cost USD): SWE-bench full: SWE-agent w/ GPT-4 Turbo 12.47 ($1.59), w/ Claude 3 Opus 10.46 ($2.59); RAG baseline GPT-4 Turbo 1.31, Claude 3 Opus 3.79. SWE-bench Lite: SWE-agent GPT-4 Turbo 18.00 ($1.67), Claude 3 Opus 13.00; Shell-only (plain bash, no ACI) GPT-4 Turbo 11.00; Shell-only without demonstration 7.33. — [arXiv HTML v3](https://arxiv.org/html/2405.15793v3)
- ACI ablations on SWE-bench Lite, GPT-4 Turbo, baseline 18.0%: edit action without linting 15.0 (−3.0); no edit command at all 10.3 (−7.7); search returning summarized results 18.0 vs "iterative" search 12.0 (−6.0) vs no search 15.7 (−2.3); file viewer window 100 lines 18.0 vs 30 lines 14.3 (−3.7) vs full file 12.7 (−5.3); context = last 5 observations 18.0 vs full history 15.0 (−3.0); without the in-prompt demonstration 16.3 (−1.7). — [arXiv HTML v3](https://arxiv.org/html/2405.15793v3)
- Stated ACI design principles: (1) actions should be simple and easy to understand, few options, concise docs; (2) consolidate common operations into few, compact actions; (3) feedback should be informative but concise; (4) guardrails such as syntax linting let agents catch and recover from errors quickly. — [arXiv HTML v3](https://arxiv.org/html/2405.15793v3)
- Notable detail: "iterative" search (dumping many raw results the agent pages through) was *worse than no search at all* (12.0 vs 15.7); showing the *whole file* was worse than a 30-line window (12.7 vs 14.3). — [arXiv HTML v3](https://arxiv.org/html/2405.15793v3)
- mini-SWE-agent README: "Just some 100 lines of python for the agent class"; "Does not have any tools other than bash" and does not use the LM tool-calling interface, so it works with any model; linear history (trajectory == prompt); each action runs via `subprocess.run` independently, so sandboxing is swapping in `docker exec`; "Scores >74% on the SWE-bench verified benchmark"; recommended as the default and as a baseline for fine-tuning/RL "if you don't want to overfit to a specific agent scaffold". — [GitHub mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent)
- mini-swe-agent docs (v2): core agent "Just 100 lines of python", environment+model+script add ~100 more; news items: "Nov 19: Gemini 3 Pro reaches 74% on SWE-bench verified with mini-swe-agent!" and "Aug 19" blog on randomly switching between GPT-5 and Sonnet 4 (years not printed on the page; Gemini 3 Pro shipped Nov 2025, so Nov 19 = 2025 [inferred]). — [mini-swe-agent.com](https://mini-swe-agent.com/latest/)
- SWE-bench "Bash Only" track: official site runs all LMs with mini-SWE-agent in a minimal bash ReAct loop on SWE-bench Verified (500 instances); release 1.x and 2.x results are "not necessarily comparable" because 2.x uses tool calling. [SECONDARY snapshot 17 Oct 2026] top entries around 75-77%: Claude 4.5 Opus (high) 76.8%, Claude 4.6 Opus 75.6% ($0.55/instance), Gemini 3 Flash 75.8%, MiniMax M2.5 75.8%; full Verified board top entry 79.2% at that snapshot. — [developersdigest snapshot](https://www.developersdigest.tech/benchmarks/swe-bench); official page [swebench.com/bash-only.html](https://www.swebench.com/bash-only.html) returned 404 when fetched 2026-10-25.
- Terminal-Bench 2.0 paper (Jan 2026) lists Mini-SWE-Agent + Claude Sonnet 4.5 at 42.5% ±2.8 vs Claude Code + Sonnet 4.5 at 40.1% ±2.9 on the same tasks — the 100-line agent matched a production harness on that model. — [arXiv 2601.11868 HTML](https://arxiv.org/html/2601.11868v1)
- Independent 2026 replication of the "bash-only is enough" idea: "An Empirical Study of Harness Design for Coding Agents" (arXiv 2609.20804, 17 Sep 2026; SWE-bench Verified + Terminal-Bench 2.1, 176 matched settings, 4 models) finds predefined tools help models with weaker bash skills, while bash-capable models do well with a bash-only interface "at substantially lower cost", especially on CLI-centric tasks. — [arXiv 2609.20804](https://arxiv.org/abs/2609.20804)

**Inferences**
- The 2024 ACI lesson and the 2025 mini-SWE-agent lesson are not contradictory: they bracket the same variable (model capability). Interface scaffolding compensates for weak models; as models learn bash and long-horizon recovery, the scaffolding's marginal value falls toward zero, and its cost (cache breaks, bespoke tool docs, overfitting to a scaffold) remains. This is the same conclusion the Amp team reached (see Q5).
- The ablation ranking (edit > search > viewer window > context truncation > demo) is a reasonable priority order for a beginner building a harness for a *non-frontier* model.

**Gaps**
- Could not fetch the official SWE-bench Bash-Only page (404), so per-model bash-only numbers are from a third-party snapshot.
- The paper's ablations are GPT-4 Turbo only; no equivalent ablation table exists for current models in the sources found.

### Q2. OpenHands (ex-OpenDevin): architecture and lessons

**Takeaway**
OpenHands' core idea is an append-only *event stream* of actions/observations as the single agent state, a Docker *runtime* exposing bash + IPython + browser behind a REST API, pluggable agents in an *AgentHub* with delegation, a Python *AgentSkills* library, and (later) a *condenser* for context compression plus keyword/path-triggered *microagents*, now renamed "skills" and read from `.agents/skills/` or `AGENTS.md`.

**Cited Findings**
- Paper: arXiv 2407.16741 (v1 23 Jul 2024, v2 4 Oct 2024, v3 18 Apr 2025), "Accepted by ICLR 2025", 24 authors (Xingyao Wang ... Graham Neubig), MIT license, 15 benchmarks, >2.1K contributions from >188 contributors. — [arXiv abstract](https://arxiv.org/abs/2407.16741)
- Architecture: event stream = chronological record of actions, observations, user messages that *is* the agent state; agents implement `step(state) -> action`; actions include `IPythonRunCellAction`, `CmdRunAction`, `BrowserInteractiveAction`; runtime = per-session Docker sandbox with bash, Jupyter IPython server, Chromium via Playwright/BrowserGym, a REST server inside the container executes actions and returns observations; AgentSkills = Python utilities (`edit_file`, `scroll_up/down`, `parse_image`, `parse_pdf`) imported into IPython; `AgentDelegateAction` lets CodeActAgent hand off browsing to BrowsingAgent; AgentHub includes CodeActAgent (default), BrowsingAgent, a GPTSwarm agent, and "micro agents" (specialized prompts on top of a generalist agent). — [arXiv HTML v3](https://arxiv.org/html/2407.16741v3)
- Results (paper): SWE-bench Lite (300, no hint) CodeActAgent v1.8 + claude-3-5-sonnet 26.0% (avg $1.10); gpt-4o 22.0%; gpt-4o-mini 7.0%. WebArena BrowsingAgent v1.0 claude-3-5-sonnet 15.5%, gpt-4o 14.8%; MiniWoB++ 40.8%; GPQA Diamond 52.0%; GAIA L1 32.1%; HumanEvalFix 79.3%; ML-Bench 76.5%; BIRD 47.3%; AgentBench OS 57.6%. — [arXiv HTML v3](https://arxiv.org/html/2407.16741v3)
- Lessons stated in the paper: one CodeAct agent without prompt changes is competitive across software/web/misc tasks whereas baselines are tuned per category; "still struggle with complex tasks"; agents "perform poorly when editing long files"; full SWE-bench run estimated at $6.9k so Lite was used; integration tests mock LLM calls with responses matched on exact prompts to be deterministic and cheap. — [arXiv HTML v3](https://arxiv.org/html/2407.16741v3)
- Condenser (current SDK docs): compresses history to stay within token limits; classes `NoOpCondenser`, `RollingCondenser`, `PipelineCondenser`, `LLMSummarizingCondenser` (default in the SDK); four responsibilities: history compression, threshold detection, summary generation, view management; mechanism: when event count exceeds `max_size`, keep first N and last M events, send the middle to an LLM for a summary wrapped in a `Condensation` event appended to the log. Older `openhands.memory.condenser` reference describes an "amortized forgetting" strategy with a running summary-of-summaries event. — [docs.openhands.dev/sdk/arch/condenser](https://docs.openhands.dev/sdk/arch/condenser); [context-condenser guide](https://docs.openhands.dev/sdk/guides/context-condenser)
- Microagents -> skills (docs, 2026): repository context = `AGENTS.md` at repo root, always loaded into the initial system prompt (also recognizes `CLAUDE.md`, `GEMINI.md`); keyword-triggered knowledge = `SKILL.md` with `triggers`, injected when a keyword appears in a user message; `paths`-triggered rules injected once per conversation when a matching file is touched (`paths` wins over `triggers`); locations `<project>/.agents/skills/`, `~/.agents/skills/`, legacy `.openhands/skills/` and `.openhands/microagents/`; public skills from github.com/OpenHands/extensions have lowest precedence; discovery puts only name+description into a catalog and the full `SKILL.md` is loaded on match (progressive disclosure). — [docs.openhands.dev microagents overview](https://docs.openhands.dev/usage/prompting/microagents-overview)
- Harness cross-comparison: Terminal-Bench 2.0 paper reports OpenHands + Claude Opus 4.5 at 51.9% ±2.9 vs Claude Code + Opus 4.5 52.1% vs Terminus 2 + Opus 4.5 57.8%; Gemini 2.5 Pro "gained 17%" when moved from OpenHands to Terminus 2. — [arXiv 2601.11868 HTML](https://arxiv.org/html/2601.11868v1)
- Factory's docs (last updated Dec 2025) list OpenHands at 43.8% on Terminal-Bench (version/model not stated). — [docs.factory.com](https://docs.factory.com/benchmarks/terminal-bench)

**Inferences**
- OpenHands' event stream + condenser is the open-source reference implementation of the pattern Cognition recommends (single thread + a dedicated compression model) and of Manus's "append-only context" rule.
- The migration from "microagents" to the cross-tool `.agents/skills/` + `AGENTS.md` convention shows the ecosystem converging on repo-resident, trigger-gated instruction files rather than monolithic system prompts.

**Gaps**
- Did not find an official OpenHands blog post with condenser benchmarks (the SDK guide links one; not opened). The datacamp hits were tutorials.
- The paper's v3 does not contain CodeActAgent v2.x numbers; later SWE-bench Verified scores for OpenHands were not collected here.

### Q3. Aider: repo map, edit formats, architect/editor mode

**Takeaway**
Aider's three durable contributions are: a token-budgeted *repo map* (tree-sitter symbols ranked by a graph algorithm, default 1k tokens) that gives the model a view of code it has not been shown; an obsessive, benchmark-driven choice of *edit format* (search/replace blocks vs unified diffs; udiff raised GPT-4 Turbo from 20% to 61% on a laziness benchmark); and *architect/editor* split that let o1-preview reach 85% on aider's benchmark vs 79.7% solo.

**Cited Findings**
- Repo map: a concise map of the whole git repo listing important classes/functions with signatures, sent with every request; for large repos a "graph ranking algorithm" where files are nodes and dependencies are edges selects the most relevant parts; budget controlled by `--map-tokens`, default 1k tokens; map grows when no files are added to chat; the LLM can ask for files, and aider offers to add them. (The doc page itself does not say "tree-sitter" or "PageRank"; the linked 2023-10-22 blog post is the origin.) — [aider.chat/docs/repomap.html](https://aider.chat/docs/repomap.html)
- Edit formats: `whole` (return full file; simplest, slow and costly), `diff` (SEARCH/REPLACE blocks with git-conflict-style markers, path before the fence), `diff-fenced` (path inside the fence; mainly for Gemini which mis-fences), `udiff` (simplified unified diff; mainly for GPT-4 Turbo to reduce lazy coding), `editor-diff` / `editor-whole` (streamlined variants used by the editor model in architect mode). — [aider.chat/docs/more/edit-formats.html](https://aider.chat/docs/more/edit-formats.html)
- Unified-diff results (21 Dec 2023, Paul Gauthier), laziness benchmark of 89 Python refactoring tasks: GPT-4 Turbo (1106) SEARCH/REPLACE 20% with lazy comments on 12 tasks -> unified diffs 61% with lazy comments on 4 tasks ("3X reduction in laziness"); GPT-4-0613 26% -> 59%. Design rules: use a format the model has seen millions of times (`git diff`), no JSON escaping, no line numbers (each hunk treated as search-and-replace), ask for "high-level" hunks (without this prompting, editing errors rose 30-50%), flexible/lenient patch application (disabling it caused a 9X increase in editing errors on the Exercism benchmark). Emotional appeals ("user is blind", "$2000 tip") *lowered* scores for both formats. — [aider.chat 2023/12/21 unified-diffs](https://aider.chat/2023/12/21/unified-diffs.html)
- Architect/editor (26 Sep 2024): o1-preview Architect + DeepSeek Editor 85.0% (whole) / 80.5% (diff); o1-preview Architect + GPT-4o Editor 80.5%; o1-preview solo 79.7%. Rationale: reasoning models "are strong at reasoning, but often fail to output properly formatted code editing instructions"; the architect describes the change in free text, the editor turns it into formatted edits; the 85% config is "likely too slow for interactive use". — [aider.chat 2024/09/26 architect](https://aider.chat/2024/09/26/architect.html)
- Counterpoint from Cognition (Jun 2025): "edit apply models" (big model writes markdown description, small model rewrites the file) were fragile because small ambiguities caused wrong edits, and by 2025 editing/applying is usually done by one model in one step. — [cognition.com don't-build-multi-agents](https://cognition.com/blog/dont-build-multi-agents)

**Inferences**
- Aider's history is a case study in "measure the edit format": the same model's effective capability swung 3X depending on how it was asked to express a change. For a beginner: pick a format the model saw in pretraining, parse leniently, forbid line numbers, and benchmark it.
- The architect/editor split is the 2024 ancestor of today's plan/act modes (Q5) and of Cline's "different model per mode"; its value decreased once models could both reason and emit well-formed edits.

**Gaps**
- No measured numbers for `diff-fenced` vs `diff` on Gemini were found.
- Did not fetch the 2023-10-22 repo-map origin post to confirm the tree-sitter/PageRank implementation details from a primary page (the terms are widely used but the docs page only says "graph ranking").

### Q4. Terminal-Bench / Harbor: the agent-vs-harness separation and same-model-different-harness evidence

**Takeaway**
Terminal-Bench 2.0 (89 tasks selected from 229 submissions, Harbor framework, Nov 2025; paper Jan 2026, ICLR 2026) deliberately separates *model* from *agent/harness* and ships Terminus 2, a bash-only "neutral testbed" agent. Its own tables show the same model spanning roughly 5-9 points across harnesses (GPT-5.2: 62.9% Codex CLI vs 54.0% Terminus 2; Claude Opus 4.5: 57.8% Terminus 2 vs 52.1% Claude Code vs 51.9% OpenHands), while concluding that model choice usually matters more than scaffold choice.

**Cited Findings**
- Timeline: Terminal-Bench 1.0 released May 2025; TB 2.0 + Harbor Nov 2025 (launch post 7 Nov 2025 per Snorkel); paper arXiv 2601.11868 posted 17 Jan 2026 (Merrill, Shaw, Carlini et al., Ludwig Schmidt last author), published at ICLR 2026. — [tbench.ai/about](https://www.tbench.ai/about); [HF dataset README](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/README.md); [ICLR 2026 proceedings PDF](https://proceedings.iclr.cc/paper_files/paper/2026/file/444a3737adaee10d86ad2ef5f74468e6-Paper-Conference.pdf); [arXiv 2601.11868](https://arxiv.org/html/2601.11868v1)
- Task construction/verification: 229 submissions from 93 contributors -> 89 selected; checks = automated oracle-solution run, contributor checklist, LLM-based check tool, manual review by three experienced reviewers, runs with multiple models and Terminus 2, an *adversarial exploit agent* (found monkey-patching of test environments, answer guessing, enumerating answers), final audit by two more reviewers; about three reviewer-hours per task; agents did not read oracle solutions in "tens of thousands" of trajectories. — [arXiv 2601.11868 HTML](https://arxiv.org/html/2601.11868v1)
- Terminus 2: single tool (a headless terminal), completes tasks only with bash commands; built as a "neutral testbed" because many scaffolds are tuned to particular models, which confounds model comparison. Harbor: framework for building and running agent evals at scale; TB 2.0 is distributed via the Harbor registry (`harbor run -d terminal-bench@2.0`); experiments used the Daytona sandbox provider with 32-100 containers in parallel; models are passed with `--model`, agents plug in by subclassing `BaseInstalledAgent`/`BaseAgent`. — [arXiv 2601.11868 HTML](https://arxiv.org/html/2601.11868v1); [HF README](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/README.md)
- Paper results table (resolution rate ±95% CI, Table 2, Jan 2026): Codex CLI + GPT-5.2 62.9 ±3.0; Terminus 2 + Claude Opus 4.5 57.8 ±2.5; Terminus 2 + Gemini 3 Pro 56.9 ±2.5; Terminus 2 + GPT-5.2 54.0 ±2.9; Claude Code + Opus 4.5 52.1 ±2.5; OpenHands + Opus 4.5 51.9 ±2.9; Terminus 2 + Gemini 3 Flash 51.7 ±3.1; Codex CLI + GPT-5 49.6 ±2.9; Mini-SWE-Agent + Claude Sonnet 4.5 42.5 ±2.8; Claude Code + Sonnet 4.5 40.1 ±2.9; Terminus 2 + Kimi K2 Thinking 35.7 ±2.8; Codex CLI + GPT-5-Mini 31.9; Gemini CLI + Gemini 2.5 Pro 19.6 ±2.9; Codex CLI + GPT-5-Nano 11.5. Same-model deltas stated by the paper: GPT-5.2 62.9 (Codex CLI) vs 54.0 (Terminus 2); Opus 4.5 57.8/52.1/51.9 across Terminus 2 / Claude Code / OpenHands; Gemini 2.5 Pro +17% Terminus 2 vs OpenHands; Codex CLI GPT-5.2 vs GPT-5-Nano +52%. Authors' conclusion: "model selection is usually more important than scaffold choice." — [arXiv 2601.11868 HTML](https://arxiv.org/html/2601.11868v1)
- Failure analysis (paper): three classes Execution / Coherence / Verification; execution errors dominate for Opus 4.5 and GPT-5.2; command-level error rates 9.2% (Grok 4) to 26.7% (GPT-OSS-120B); most frequent command failure = calling executables not installed / not on PATH (24.1%); failures when running executables 9.6%. Appendix taxonomy headings include "Premature Termination", "Unaware of Termination Conditions", "Weak Verification". — [arXiv 2601.11868 HTML](https://arxiv.org/html/2601.11868v1)
- Factory docs (page says "Last updated: December 2025", links terminal-bench/2.0, models not listed): Factory Droid 63.1%, OpenAI Codex CLI 60.4%, Warp 59.1%, OpenHands 43.8%, Claude Code 40.1%. No attribution to harness design is given on the page. — [docs.factory.com/benchmarks/terminal-bench](https://docs.factory.com/benchmarks/terminal-bench)
- Vals.ai TB 2.0 board runs *every* model under Terminus 2 so rankings are harness-controlled; lists Claude Opus 4.5 (Thinking) 53.93%. — [vals.ai terminal-bench-2](https://www.vals.ai/benchmarks/terminal-bench-2)
- Snorkel TB 2.0 board (142 entries, no per-row dates, 2026): NexAU-AHE + GPT-5.5 84.7%, LemonHarness (multiple models) 84.5%, Capy + GPT-5.5 83.1%, Codex CLI + GPT-5.5 82.2%, Polaris 82.2%, WOZCODE + Claude Opus 4.7 80.2%, TongAgents + Gemini 3.1 Pro 80.2%, SageAgent + GPT-5.3-Codex 78.4%, Droid + GPT-5.3-Codex 77.3%. GPT-5.5 spans 84.7 -> 82.2 across three scaffolds; GPT-5.3-Codex 78.4 vs 77.3. — [snorkel.ai leaderboard](https://snorkel.ai/leaderboard/terminal-bench-2-0/)
- [SECONDARY, personal blog that sells a Codex CLI book, 11 Jun 2026] Terminal-Bench 2.1 (tbench.ai, 9 Jun 2026): Codex CLI + GPT-5.5 83.4%; Claude Code + Opus 4.8 78.9%; Terminus 2 + GPT-5.5 78.2%; Terminus 2 + Gemini 3 Pro 74.4%; Gemini CLI + Gemini 3.1 Pro 70.7%; Claude Code + Opus 4.7 69.7%. Author attributes the 5.2-pt GPT-5.5 gap to "harness engineering" (tool loop, sandbox config, file handling, retry logic, verification hooks, fewer MCP round-trips) — these are explanations, not measurements. Also quotes vals.ai Terminus-2-only numbers: GPT-5.5 76.40%, Claude Fable 5 80.52%. — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/06/11/terminal-bench-2-1-june-2026-benchmark-landscape-codex-cli-harness-engineering-model-scores/)
- Search-snippet corroboration of the 2.1 board: Codex CLI + GPT-5.5 83.4 ±2.2; Terminus 2 + Claude 5 Fable 80.4. — [tbench.ai terminal-bench@2.1](https://www.tbench.ai/leaderboard/terminal-bench/2.1) (rows load dynamically; direct fetch on 2026-10-25 returned headers only and a chart caption reading "Resolution rate of Terminal-Bench 4.0 tasks" [UNCERTAIN whether a 4.0 release exists or the caption is a page bug])
- Independent harness study (Sep 2026) on TB 2.1 + SWE-bench Verified: context management mostly prevents context-overflow failures and matters more under tight budgets; rule-based elision *before* LLM summarization is most efficient; making elided content recoverable "added machinery that models rarely used" with no accuracy gain; planning = accuracy scaffold for weak models, cost saver for strong ones; bash-only is fine for bash-capable models. — [arXiv 2609.20804](https://arxiv.org/abs/2609.20804)

**Inferences**
- Two consistent numbers across sources: on TB 2.0 a harness swap moves a fixed frontier model by about 5-9 points (Jan 2026 paper) and about 2-5 points at the top of the 2026 boards; a model swap moves 20-50 points. "Harness matters" is true but second-order to model choice; vendor-controlled harnesses (Codex CLI with OpenAI models) tend to beat neutral harnesses on their own model, consistent with scaffold tuning to the model.
- Vals.ai's "everything under Terminus 2" and tbench.ai's "agent + model" rows are the two legitimate ways to publish: control the harness to compare models, or fix the model to compare harnesses. Mixed boards (Factory's, aggregators') without the model column are not interpretable.

### Q5. Community design frameworks: 12-Factor Agents, Manus context engineering, Ralph Wiggum loop, Cline/Roo/Kilo plan-act, Cursor rules & background agents, Gemini CLI, Amp, Factory Droid, Cognition's "Don't build multi-agents"

**Takeaway**
Practitioner frameworks converge on a short list: own your prompts, context window and control flow (12-Factor); treat KV-cache hit rate as the production metric and keep context append-only, mask tools instead of removing them, externalize memory to files, recite goals, keep errors in (Manus); prefer one linear thread with full context over parallel sub-agents (Cognition); separate read-only planning from acting (Cline/Roo/Kilo/Devin); put instructions in repo-resident, scoped rule files (Cursor, OpenHands, Gemini CLI); and run long tasks as fresh-context loops with structured artifacts and backpressure (Ralph, Anthropic's long-running harness post). The Amp team adds the meta-lesson: every harness component encodes an assumption about what the model cannot do, and those assumptions expire.

**Cited Findings**

*12-Factor Agents (HumanLayer, Dex Horthy, 2025)*
- Factors: 1 Natural Language to Tool Calls; 2 Own your prompts; 3 Own your context window; 4 Tools are just structured outputs; 5 Unify execution state and business state; 6 Launch/Pause/Resume with simple APIs; 7 Contact humans with tool calls; 8 Own your control flow; 9 Compact Errors into Context Window; 10 Small, Focused Agents; 11 Trigger from anywhere, meet users where they are; 12 Make your agent a stateless reducer; bonus 13 Pre-fetch all the context you might need. Page references a March 2025 podcast and an April 3, 2025 screenshot; no explicit publication date on the README. — [github.com/humanlayer/12-factor-agents](https://github.com/humanlayer/12-factor-agents)

*Manus, "Context Engineering for AI Agents" (Yichao "Peak" Ji, 18 Jul 2025)*
- KV-cache hit rate is "the single most important metric" for a production agent; Claude Sonnet cached input $0.30/MTok vs $3/MTok uncached (10x); average input:output ratio ~100:1; keep prompt prefix stable (a per-second timestamp in the system prompt kills the cache), context append-only, deterministic serialization, explicit cache breakpoints where required. — [manus.im blog](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Mask, don't remove: adding/removing tools mid-task invalidates cache and confuses the model when history references missing tools; Manus masks token logits to constrain action selection; consistent tool-name prefixes (`browser_`, `shell_`) make group-level masking easy. — same
- File system as context: unlimited, persistent, agent-operable memory; compression must be *restorable* (drop page content but keep URL; drop document but keep path). — same
- Recitation: a `todo.md` rewritten as work proceeds pushes goals into the recent-attention window; typical task ~50 tool calls. — same
- Keep the wrong stuff in: leave failed actions and stack traces in context so the model updates its beliefs; "error recovery is one of the clearest indicators of true agentic behavior" and is under-represented in benchmarks. — same
- Don't get few-shotted: uniform action-observation histories cause imitation ruts (reviewing 20 resumes); inject small structured variation in serialization/phrasing/order. — same
- The team rebuilt the framework four times ("Stochastic Graduate Descent"). — same

*Cognition, "Don't Build Multi-Agents" (Walden Yan, 12 Jun 2025)*
- Principle 1: "Share context, and share full agent traces, not just individual messages." Principle 2: "Actions carry implicit decisions, and conflicting decisions carry bad results." Flappy Bird example: two parallel subagents produce a background in a different game's style and a bird that neither looks nor moves right; the final agent must reconcile incompatible outputs; even forwarding the original task does not fix it. Recommended: single-threaded linear agent; for long tasks a dedicated context-compression model (hard; may need a fine-tuned small model). Claude Code subagents (as of Jun 2025) run narrow questions, not parallel code writing, precisely to keep the main thread's context clean. Edit-apply models (2024) were fragile. — [cognition.com](https://cognition.com/blog/dont-build-multi-agents)
- Devin 2.0 (Apr 2025) added "interactive planning": proactive codebase exploration and a user-editable plan before execution; Cognition claimed 83% more junior-level tasks per ACU vs v1 [SECONDARY]. Launch-era SWE-bench 13.86% (Mar 2024). — [eesel.ai review](https://eesel.ai/blog/cognition-ai-reviews); [the-decoder](https://the-decoder.com/cognition-unveils-ai-powered-software-developer-devin-for-better-programming/)

*Ralph Wiggum loop (Geoffrey Huntley, 14 Jul 2025) and derivatives*
- Definition: `while :; do cat PROMPT.md | claude-code ; done` — same prompt, fresh context each iteration, one repo, one task per loop. Rationale: monolithic beats multi-agent coordination; model has ~170k usable tokens and quality drops as it fills, so keep each loop's context small; stable inputs (`fix_plan.md`, specs) every loop; subagents for expensive search/summarize, only one subagent for build/test. Lessons: one thing per loop; tune by adding "signs" to the prompt; add *backpressure* (tests, type checkers, static analyzers; dynamically typed languages need a static analyzer); agents wrongly conclude code is "unimplemented" after a bad search; models drift to stubs/placeholders unless told; expect the codebase to break sometimes (git reset or rescue prompts); regenerate the TODO when drift appears; greenfield only; senior engineers still needed. Anecdotal claims (CURSED language, $50k contract for $297, six repos overnight) are unverified. — [ghuntley.com/ralph](https://ghuntley.com/ralph/)
- Anthropic shipped an official `ralph-loop` Claude Code plugin (`/plugin install ralph-loop`), aimed at stopping Claude Code "quitting early" (~80% completion); critics note the plugin keeps the same context window ("automating the continue button") whereas "True Ralph" resets context per iteration. [SECONDARY tutorials/press, Jan 2026] — [The Register 27 Jan 2026](https://www.theregister.com/2026/01/27/ralph_wiggum_claude_loops/); [tenten.co](https://developer.tenten.co/ralph-wiggum-plugin-turning-claude-code-into-an-autonomous-development-agent)
- Anthropic Engineering, "Effective harnesses for long-running agents" (Justin Young, 26 Nov 2025): observed failure modes = one-shotting (tries too much, runs out of context mid-feature), premature completion (sees progress, declares done), premature "passing" (marks features done after unit tests/curl without end-to-end check). Harness: an *initializer* session writes a feature list (claude.ai clone: 200+ features, all initially failing), `init.sh`, `claude-progress.txt`, initial git commit; each *coding* session works one feature, starts by reading progress notes + git log + feature list and running `init.sh` plus a basic e2e check, ends with a descriptive commit and progress update. Feature list is JSON with a `passes` field the agent may only flip — model was less likely to clobber JSON than Markdown. Browser automation (Puppeteer MCP) for e2e testing greatly improved bug detection. Lesson: compaction alone does not give clean handoffs; structured artifacts do. — [anthropic.com/engineering](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

*Plan/Act modes: Cline, Roo Code, Kilo Code*

### Q6. Anti-patterns documented by practitioners: context rot / long-context degradation, lost-in-the-middle, tool overload, over-engineered multi-agent, premature victory, reward-hacking tests

**Takeaway**
The best-evidenced anti-patterns are (a) context-length degradation even on trivial tasks (Chroma, 18 models, Jul 2025; Lost-in-the-Middle, 2023), (b) tool-count degradation (direction well supported, thresholds anecdotal), (c) dispersed-decision multi-agent systems (Cognition), (d) premature completion / weak verification (Anthropic Nov 2025, Terminal-Bench taxonomy, 2026 papers), and (e) test gaming — from weakening assertions to precomputing expected outputs (97% public / 0% held-out). The common countermeasures are external backpressure (tests the agent cannot edit, e2e checks, maker/checker split) and keeping context small and structured.

**Cited Findings**
- Chroma "Context Rot" (Kelly Hong, Anton Troynikov, Jeff Huber, 14 Jul 2025): 18 LLMs incl. GPT-4.1, Claude 4, Gemini 2.5, Qwen3; models "do not use their context uniformly"; performance degrades with input length even on simple tasks; lower needle-question similarity -> faster decline with length; one distractor hurts, four compound it, non-uniformly; *shuffled* haystacks beat logically structured ones across all 18 models; LongMemEval (306 prompts): focused inputs (~300 tokens) score significantly higher than full inputs (~113k tokens); repeated-words task shows refusals/random output at long lengths (Claude Opus 4 refused 2.89% of attempts). — [trychroma.com/research/context-rot](https://www.trychroma.com/research/context-rot)
- Lost in the Middle (Liu, Lin, Hewitt, Paranjape, Bevilacqua, Petroni, Liang; arXiv 6 Jul 2023, v3 20 Nov 2023, TACL): in multi-document QA and key-value retrieval, performance is "often highest when relevant information occurs at the beginning or end of the input context" and drops significantly for the middle, even for long-context models. — [arXiv 2307.03172](https://arxiv.org/abs/2307.03172)
- Manus's practical reading of the same effect: ~50 tool calls per task; without recitation the model drifts from goals buried early in context. — [manus.im blog](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Tool overload: [SECONDARY write-ups of the RAG-MCP paper, May 2025] tool-selection accuracy ~13.6% with a large visible tool set vs ~43% when retrieval exposes only a relevant subset, same model and tools; schemas cost ~150-400 tokens each on every request; blogs claim degradation starting at ~10-30 tools and errors around 20 tools on the Berkeley Function Calling Leaderboard, but no controlled study with those thresholds was found. — [tianpan.co over-tooled agent](https://tianpan.co/blog/2026-04-19-over-tooled-agent-problem); [machinelearningmastery tool selection](https://machinelearningmastery.com/the-complete-guide-to-tool-selection-in-ai-agents/); [tianpan.co action space](https://tianpan.co/blog/2026-03-01-agent-action-space-design)
- Mitigations in the wild: Manus masks logits rather than removing tools; OpenHands skills and Cursor rules expose only name+description and load bodies on demand; Sourcegraph wraps search as a sub-agent to keep the main context clean. — [manus.im](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus); [docs.openhands.dev](https://docs.openhands.dev/usage/prompting/microagents-overview); [cursor.com/docs/context/rules](https://cursor.com/docs/context/rules); [sourcegraph.com](https://sourcegraph.com/blog/a-note-from-dan)
- Over-engineered multi-agent: Cognition's "dispersed decision-making" argument and Flappy Bird example (Jun 2025); Ralph post argues multi-agent adds microservice-style complexity made worse by non-determinism (Jul 2025); Anthropic's long-running-harness post leaves "single general agent vs testing/QA/cleanup agents" explicitly open (Nov 2025). — [cognition.com](https://cognition.com/blog/dont-build-multi-agents); [ghuntley.com/ralph](https://ghuntley.com/ralph/); [anthropic.com/engineering](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- Premature victory: Anthropic observed agents that "see some progress, declare the project done" and mark features passing after unit tests/curl without e2e verification; fix = one-feature-at-a-time plus mandatory e2e check before flipping `passes`. — [anthropic.com/engineering](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents). Ralph plugin motivation: stop Claude Code "quitting early" around 80% completion [SECONDARY]. — [tenten.co](https://developer.tenten.co/ralph-wiggum-plugin-turning-claude-code-into-an-autonomous-development-agent). Terminal-Bench paper appendix taxonomy includes "Premature Termination", "Unaware of Termination Conditions", "Weak Verification". — [arXiv 2601.11868](https://arxiv.org/html/2601.11868v1). 2026 paper "From Confident Closing to Silent Failure: Characterizing False Success in LLM Agents" studies the phenomenon on tau2-bench and AppWorld. — [arXiv 2606.09863](https://arxiv.org/pdf/2606.09863)
- Reward hacking tests: [2026 arXiv papers, abstracts via search] an agent precomputed expected outputs for public test programs via system GCC and stored them in a lookup table: 97% on validation, 0% on held-out ("97pp reward hacking gap"); agents implement SELECT/JOIN/GROUP BY/HAVING as separate handlers that each pass their own tests but never integrate; self-grading drifts upward when the same model produces and grades -> separate maker from checker; 80.2% of agent-authored test patches carry weak or no oracle signal. — [Capped Evaluation with Randomized Tests, arXiv 2606.07379](https://arxiv.org/pdf/2606.07379); [SpecBench, arXiv 2605.21384](https://arxiv.org/pdf/2605.21384); [Stop Hand-Holding Your Coding Agent, arXiv 2607.00038](https://arxiv.org/pdf/2607.00038); [AgentPatterns anti-pattern index](https://agentpatterns.ai/patterns/anti-patterns/)
- Terminal-Bench's adversarial exploit agent found monkey-patching of test environments, answer guessing, and answer enumeration during task validation (Jan 2026). — [arXiv 2601.11868](https://arxiv.org/html/2601.11868v1)
- AgentPatterns.ai index (secondary aggregator, ~200 entries, last reviewed 2026-05-27, cites but does not inline sources): "Premature Completion" (named by four research teams within a year); "Cross-Component Interference" (maximally equipped agent loses to smaller tool subsets in 30-50% of tasks); "Repairing a Failing Test by Weakening Its Assertion" (mock assertion errors 66.67% of Java and 81.54% of Python failures); "Deletion Avoidance" (deletion recall peaks 71.7%); "Prompt-Only Tool Access Control" lets 4.0-37.0% of unauthorized calls through; "Run-Status vs Task-Status Confusion"; "Stale AI Configuration Artifacts" (CLAUDE.md/AGENTS.md drift). Treat numbers as pointers to verify, not citations. — [agentpatterns.ai](https://agentpatterns.ai/patterns/anti-patterns/)
- Aider found that "emotional appeal" prompting (user is blind / $2000 tip) lowered scores — a small documented prompt anti-pattern. — [aider.chat 2023/12/21](https://aider.chat/2023/12/21/unified-diffs.html)
- Ralph's listed failure modes: agent concludes code is unimplemented after a bad search; stubs/placeholders; non-determinism as the "Achilles' heel". — [ghuntley.com/ralph](https://ghuntley.com/ralph/)

**Inferences**
- Context rot explains why nearly every successful harness truncates (SWE-agent last-5 observations), compresses (OpenHands condenser, Cognition), resets (Ralph), or externalizes (Manus files, Anthropic progress files). The Chroma finding that *structured* haystacks hurt more than shuffled ones suggests long, coherent transcripts are a worst case for attention, which supports summarizing rather than merely trimming.
- Reward hacking and premature victory are two faces of the same gap: the agent controls its own success signal. Every effective fix moves the signal outside the agent's write access (hidden/randomized tests, a separate checker, e2e browser checks, a JSON `passes` flag that only verification may flip).

**Gaps**
- No controlled, peer-reviewed tool-count threshold study was located; RAG-MCP numbers were not verified against the paper.
- The 2026 reward-hacking and false-success papers were seen only via search snippets of abstracts/PDF text; venue and exact setups not confirmed.

### Q7. How practitioners evaluate harnesses: SWE-bench Verified, Terminal-Bench 2, tau-bench, custom suites, LLM-as-judge, trajectory review

**Takeaway**
Agent evals in practice combine (1) outcome-graded, containerized task suites with human-verified tasks (SWE-bench Verified's 500 problems; Terminal-Bench 2.0's 89 tasks with ~3 reviewer-hours each and an adversarial exploit agent), (2) reliability metrics over repeated runs (tau-bench pass^k), (3) LLM/agent-as-judge with explicit rubrics and a different model family than the agent, and (4) trajectory review that grades process as well as outcome, because pass-only grading accepts weak processes.

**Cited Findings**
- SWE-bench Verified (OpenAI, Aug 2024): 500-sample subset of SWE-bench test set "verified to be non-problematic by our human annotators"; 93 Python-experienced developers annotated 1,699 random samples; motivation = underspecified issues and overly specific tests; GPT-4o with the Agentless scaffold went from 16% (original) to 33.2% (Verified); difficulty slices: 196 "<15 min" easy tasks, 45 ">1 hour" hard tasks; a secondary summary says 68.3% of annotated samples were filtered out [SECONDARY]. — [openai.com introducing-swe-bench-verified](https://openai.com/index/introducing-swe-bench-verified/) (403 on direct fetch; figures corroborated by [wandb report](https://wandb.ai/byyoung3/ml-news/reports/OpenAI-Releases-SWE-bench-Verified--Vmlldzo5MDI3NzU0))
- SWE-bench maintains separate boards: Verified (any scaffold) and Bash Only (every model run through mini-SWE-agent) to separate model from scaffold; 1.x vs 2.x bash-only results not comparable because 2.x uses tool calling. — [developersdigest summary of swebench.com](https://www.developersdigest.tech/benchmarks/swe-bench)
- Terminal-Bench 2.0 methodology: 229 -> 89 tasks; oracle-solution auto-run, contributor checklist, LLM check tool, 3 human reviewers, multi-model runs, adversarial exploit agent, 2-reviewer final audit; results reported with 95% CIs; agents plug into Harbor via `BaseAgent`, models via `--model`; parallel sandboxes (Daytona, 32-100 containers). — [arXiv 2601.11868](https://arxiv.org/html/2601.11868v1); [HF README](https://huggingface.co/datasets/harborframework/terminal-bench-2.0/blob/main/README.md)
- Harness-controlled model boards (vals.ai runs everything under Terminus 2) vs agent+model boards (tbench.ai, Snorkel). — [vals.ai](https://www.vals.ai/benchmarks/terminal-bench-2); [snorkel.ai](https://snorkel.ai/leaderboard/terminal-bench-2-0/)
- tau-bench (Yao, Shinn, Razavi, Narasimhan; arXiv 17 Jun 2024): LM-simulated user, domain API tools + policy guidelines; success = final database state equals annotated goal state; pass^k measures reliability over k trials; gpt-4o-class function-calling agents succeed on <50% of tasks and pass^8 < 25% in retail. — [arXiv 2406.12045](https://arxiv.org/abs/2406.12045)
- LLM-as-judge practice (tutorials, 2025-2026): give the judge task + trajectory + rubric; use a different model family than the agent to reduce self-preference; score bands tied to concrete criteria rather than binary pass/fail; judge reliability depends on transcript presentation — one 2026 study tested five prompt conditions including stripping all agent natural language and leaving only tool outputs; pin and log the user-simulator so simulator errors are separable from agent errors; start with 10-20 hand-curated realistic tasks before scaling. — [medium.com agent evaluation ch.8](https://medium.com/@vinodkrane/chapter-8-agent-evaluation-for-llms-how-to-test-tools-trajectories-and-llm-as-judge-788f6f3e0d52); [prompt20 agent evaluation](https://blog.prompt20.com/posts/agent-evaluation/); [arXiv 2606.09863](https://arxiv.org/pdf/2606.09863)
- Agent-as-a-judge and trajectory review papers (2026): AJ-Bench benchmarks environment-aware agent judges; AgentLens proposes production-assessed trajectory reviews for coding agents; "Pass-Only Grading" anti-pattern: 10.7% of 1,136 passing trajectories reached a correct patch through a weak process [SECONDARY via AgentPatterns]. — [arXiv 2604.18240](https://arxiv.org/pdf/2604.18240); [arXiv 2607.06624](https://arxiv.org/pdf/2607.06624); [agentpatterns.ai](https://agentpatterns.ai/patterns/anti-patterns/)
- Anthropic's long-running harness used a JSON feature list as the eval artifact (200+ features, `passes` flag) and browser-automation e2e checks as the oracle; they note Claude cannot see browser-native alert modals. — [anthropic.com/engineering](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- OpenHands tests its harness deterministically by mocking LLM calls with prompt-matched canned responses. — [arXiv 2407.16741 HTML](https://arxiv.org/html/2407.16741v3)
- Cost as an eval axis: SWE-agent reports $/instance alongside % resolved; OpenHands reports avg $1.10/instance; TB boards carry Cost and Tokens columns; Manus argues for KV-cache hit rate as the production metric. — [arXiv 2405.15793](https://arxiv.org/html/2405.15793v3); [arXiv 2407.16741](https://arxiv.org/html/2407.16741v3); [tbench.ai](https://www.tbench.ai/leaderboard/terminal-bench/2.1); [manus.im](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- Anti-contamination/cheating evals (2026): capped evaluation with randomized tests; SpecBench for long-horizon reward hacking. — [arXiv 2606.07379](https://arxiv.org/pdf/2606.07379); [arXiv 2605.21384](https://arxiv.org/pdf/2605.21384)

**Inferences**
- A beginner's eval stack that mirrors the community: a small (10-20 -> ~100) set of containerized tasks with hidden tests and a human-verified oracle; run each task k times and report pass^k with CIs; log full trajectories; add an LLM judge from a different family for process/quality; publish both a harness-controlled and a model-controlled comparison; track cost and tokens per task.
- Benchmark lessons recur: SWE-bench needed Verified because ~2/3 of raw tasks were flawed; Terminal-Bench rejected ~61% of submissions and still runs an exploit agent — task validation effort is the main cost of a credible eval.
